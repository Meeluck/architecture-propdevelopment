# Задание 1. Разработка проверочного листа по безопасности данных

Первым делом нужно разработать проверочный лист по безопасности данных. Сейчас это ключевая проблема компании и самое уязвимое место.

Чтобы создать документ, выполните четыре шага.

1. Проанализируйте диаграмму и описание системы PropDevelopment

    Классифицируйте типы данных, с которыми работает компания, по стандартам ISO/IEC 27001 и 27002. Распределите их по четырём категориям:

    - публичные данные,
    - внутренние данные,
    - конфиденциальные данные,
    - секретные данные.

2. Определите риски для каждой категории данных

    В каждой категории данных могут существовать следующие риски:

    - утечка данных,
    - потеря данных,
    - искажение данных,
    - некачественные данные,
    - обесценивание данных.

3. Объясните, почему именно этот риск актуален для указанной категории данных

4. Дайте оценку каждому риску

    В качестве шкалы используйте категории «незначительный-значительный-критический».

5. Визуализируйте результаты анализа в виде mindmap

Для создания mindmap используйте draw.io. В центре разместите блок «Безопасность данных». От него протяните стрелочки и разместите следующий уровень — выделенные категории данных. На следующем уровне укажите, какие именно данные компании относятся к этой категории. Для каждого типа данных укажите риск и присвойте ему оценку. На последнем уровне объясните, почему вы оценили риск именно так.

Когда mindmap будет готов, загрузите его в директорию Task1 вашего репозитория.

## Типы данных

### 1. Публичные данные

**1.1 Данные онлайн-витрины недвижимости** - к этим данным относятся сведения, которые клиент видит на онлайн-витрине для подбора и бронирования недвижимости: объекты, параметры, статусы доступности, описание и условия бронирования.

| Риск                          | Почему риск актуален                                                                                                                        | Оценка             |
| ----------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | ------------------ |
| Искажение данных              | Если на витрине отображается неверная цена, статус квартиры или описание объекта, клиент может принять неправильное решение о бронировании. | **значительный**   |
| Потеря / недоступность данных | Если данные витрины недоступны, клиент не сможет подобрать или забронировать объект.                                                        | **значительный**   |
| Обесценивание данных          | Если данные устарели, например объект уже забронирован, но отображается как доступный, информация теряет практическую ценность.             | **значительный**   |
| Утечка данных                 | Для публичной витрины риск утечки не является ключевым, если наружу выводятся только публичные сведения.                                    | **незначительный** |

---

### 2. Внутренние данные

**2.1. Операционные данные по осмотрам, бронированию и сопровождению клиента** - этим данным относятся статусы осмотров, факты бронирования, результаты онлайн-тура или офлайн-осмотра, рабочие комментарии менеджеров и другая информация, используемая для сопровождения продажи.

| Риск                  | Почему риск актуален                                                                                                                    | Оценка           |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Потеря данных         | Результаты осмотров и бронирований фиксируются в IT-системах, поэтому их потеря может нарушить процесс продажи и сопровождения клиента. | **значительный** |
| Искажение данных      | Некорректный статус осмотра или бронирования может привести к ошибкам в дальнейшей работе с клиентом.                                   | **значительный** |
| Некачественные данные | Из-за нескольких точек регистрации клиента данные могут быть неполными, дублирующимися или несогласованными.                            | **значительный** |

---

**2.2. Данные об объектах недвижимости** - к этим данным относятся внутренние сведения об объектах недвижимости: параметры квартир, статусы доступности, связь объекта с бронированием, данные для витрины и сервисов продаж.

| Риск                  | Почему риск актуален                                                                                                                    | Оценка           |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Искажение данных      | Если статусы объектов или параметры недвижимости расходятся между системами, менеджеры и клиенты будут видеть разные данные.            | **значительный** |
| Некачественные данные | Данные используются несколькими сервисами продаж, поэтому несогласованность между системами может привести к противоречивой информации. | **значительный** |
| Обесценивание данных  | Если данные об объектах не обновляются вовремя, они перестают быть полезными для продаж и аналитики.                                    | **значительный** |

---

**2.3. Внутренние данные сервисов ЖКХ** - к этим данным относятся сведения о ремонтах, обращениях, информации от управляющей компании и других операционных процессах ЖКХ.

| Риск                  | Почему риск актуален                                                                                                                                  | Оценка           |
| --------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Искажение данных      | Если данные по ремонтам, начислениям или обращениям некорректны, собственник может получить неправильную информацию или выполнить ошибочное действие. | **значительный** |
| Некачественные данные | Данные могут поступать из систем PropDevelopment и партнёрских систем УК без единых политик контроля.                                                 | **значительный** |
| Потеря данных         | Потеря данных по обращениям, ремонтам или начислениям может нарушить обслуживание собственников.                                                      | **значительный** |

---

**2.4. Данные DWH, BI и отчётности** - к этим данным относятся данные хранилища, отчётов, аналитических витрин и BI-инструментов. Сам DWH можно считать внутренней системой, но внутри него могут оказаться данные разных категорий: внутренние, конфиденциальные и секретные.

| Риск                  | Почему риск актуален                                                                                                                        | Оценка          |
| --------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- | --------------- |
| Некачественные данные | В компании нарушен системный контроль внутренних потоков данных, поэтому в DWH могут попадать неполные, дублирующиеся или ошибочные данные. | **критический** |
| Обесценивание данных  | Если в DWH попадают лишние, грязные или несогласованные данные, аналитика теряет практическую ценность.                                     | **критический** |
| Утечка данных         | Со стороны систем обработки данных нет ограничений на доступ к данным, поэтому в DWH могут оказаться чувствительные сведения.               | **критический** |

---

### 3. Конфиденциальные данные

**3.1. Персональные данные клиентов** - к этим данным относятся ФИО, телефон, email, данные расширенной формы, сведения, связанные с бронированием и дальнейшим сопровождением клиента.

| Риск                  | Почему риск актуален                                                                                         | Оценка           |
| --------------------- | ------------------------------------------------------------------------------------------------------------ | ---------------- |
| Утечка данных         | Клиент при бронировании указывает ФИО, телефон, email и может заполнить расширенную форму для онлайн-сделки. | **критический**  |
| Искажение данных      | Ошибки могут привести к некорректному сопровождению клиента или отображению чужих данных в личном кабинете.  | **критический**  |
| Некачественные данные | Есть несколько точек регистрации нового клиента без координации между ними.                                  | **значительный** |

---

**3.2. Персональные данные собственников** - к этим данным относятся ФИО, контактные данные, связь собственника с объектом недвижимости, данные личного кабинета, данные взаимодействия с УК и сервисами ЖКХ.

| Риск                  | Почему риск актуален                                                                                               | Оценка           |
| --------------------- | ------------------------------------------------------------------------------------------------------------------ | ---------------- |
| Утечка данных         | CRM и сервисы ЖКХ управляют данными собственников, которые могут стать доступны другому пользователю или партнёру. | **критический**  |
| Искажение данных      | Некорректная связка собственника, объекта недвижимости или данных ЖКХ может привести к отображению чужих сведений. | **критический**  |
| Некачественные данные | Данные собственников могут поступать из внутренних CRM и партнёрских систем УК.                                    | **значительный** |

---

**3.3. Данные партнёрских API управляющих компаний** - к этим данным относятся данные, которые передаются между PropDevelopment и системами управляющих компаний.

| Риск                  | Почему риск актуален                                                                                                              | Оценка           |
| --------------------- | --------------------------------------------------------------------------------------------------------------------------------- | ---------------- |
| Утечка данных         | API управляющих компаний используются без единых политик безопасности и могут содержать персональные данные.                      | **критический**  |
| Искажение данных      | Некоторые контракты позволяют внешним пользователям выполнять действия и изменять данные, к которым у них не должно быть доступа. | **критический**  |
| Некачественные данные | Интеграции с партнёрами выполняются без системного контроля состава и качества передаваемых данных.                               | **значительный** |

---

**3.4. Данные финансового учёта** - к этим данным относятся данные системы финансового учёта.

| Риск             | Почему риск актуален                                                                                | Оценка           |
| ---------------- | --------------------------------------------------------------------------------------------------- | ---------------- |
| Утечка данных    | Финансовые данные используются для бухгалтерского учёта, сверок, отчётности и платежей.             | **критический**  |
| Потеря данных    | Потеря финансовых записей может нарушить сверки, отчётность и обработку платежей.                   | **значительный** |
| Искажение данных | Ошибка в начислениях, оплатах или бухгалтерских операциях может привести к финансовым расхождениям. | **критический**  |

---

**3.5. Данные авторизации и связки пользователя с профилем** - к этим данным относятся роли, права доступа, связи пользователя с клиентским или собственническим профилем, а также настройки доступа к данным.

| Риск             | Почему риск актуален                                                                                              | Оценка          |
| ---------------- | ----------------------------------------------------------------------------------------------------------------- | --------------- |
| Искажение данных | Если права доступа или связка пользователя с профилем настроены неверно, пользователь может увидеть чужие данные. | **критический** |
| Утечка данных    | Ошибки в доступах могут раскрыть данные клиента, собственника или объекта не тому пользователю.                   | **критический** |

---

### 4. Секретные данные

**4.1. Данные онлайн-сделок** -  к этим данным относятся параметры онлайн-сделки, этапы её прохождения, юридически значимые статусы, данные взаимодействия с государственными органами и информация, необходимая для покупки недвижимости онлайн.

| Риск             | Почему риск актуален                                                                             | Оценка          |
| ---------------- | ------------------------------------------------------------------------------------------------ | --------------- |
| Утечка данных    | Онлайн-сделка содержит юридически и финансово значимую информацию клиента.                       | **критический** |
| Искажение данных | Искажение параметров сделки может привести к юридически значимым ошибкам.                        | **критический** |
| Потеря данных    | Потеря данных сделки может остановить процесс покупки или нарушить взаимодействие с госорганами. | **критический** |

---

**4.2. Документы и данные для регистрации сделки**.

| Риск             | Почему риск актуален                                                                           | Оценка          |
| ---------------- | ---------------------------------------------------------------------------------------------- | --------------- |
| Утечка данных    | Документы регистрации могут содержать персональные, имущественные и финансовые сведения.       | **критический** |
| Потеря данных    | Потеря документов или статусов регистрации может остановить сделку.                            | **критический** |
| Искажение данных | Некорректные данные регистрации могут привести к ошибочной или невозможной регистрации сделки. | **критический** |

---

**4.3. Данные управления “Умным домом”** - к этим данным относятся команды и состояния, связанные с управлением автоматикой в помещении и на этажах, а также устройством, которое запирает квартиру.

| Риск             | Почему риск актуален                                                                                                | Оценка          |
| ---------------- | ------------------------------------------------------------------------------------------------------------------- | --------------- |
| Утечка данных    | Данные управления “Умным домом” могут раскрыть сведения об устройстве помещения, доступах или сценариях управления. | **критический** |
| Искажение данных | Изменение команд или состояний устройств может привести к некорректной работе автоматики или замка.                 | **критический** |

---

**4.4. Критичные интеграционные и технические данные** - к этим данным относятся API-ключи, токены, секреты интеграций, служебные учётные записи и параметры доступа к внешним системам.

| Риск             | Почему риск актуален                                                                                          | Оценка           |
| ---------------- | ------------------------------------------------------------------------------------------------------------- | ---------------- |
| Утечка данных    | API-ключи, токены, секреты интеграций и служебные учётные записи могут дать доступ к системам.                | **критический**  |
| Потеря данных    | Потеря ключей, токенов или параметров интеграций может нарушить работу сервисов и обмен с внешними системами. | **значительный** |
| Искажение данных | Изменение параметров интеграций может перенаправить данные или нарушить корректность обмена.                  | **критический**  |
