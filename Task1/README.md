# Задание 1. Разработка проверочного листа по безопасности данных

Первым делом нужно разработать проверочный лист по безопасности данных. Сейчас это ключевая проблема компании и самое уязвимое место.

Чтобы создать документ, выполните четыре шага.

1. Проанализируйте диаграмму и описание системы PropDevelopment

    Классифицируйте типы данных, с которыми работает компания, по стандартам ISO/IEC 27001 и 27002. Распределите их по четырём категориям:

    - публичные данные,
    - внутренние данные,
    - конфиденциальные данные,
    - секретные данные.

2. Определите риски для каждой категории данных

    В каждой категории данных могут существовать следующие риски:

    - утечка данных,
    - потеря данных,
    - искажение данных,
    - некачественные данные,
    - обесценивание данных.

3. Объясните, почему именно этот риск актуален для указанной категории данных

4. Дайте оценку каждому риску

    В качестве шкалы используйте категории «незначительный-значительный-критический».

5. Визуализируйте результаты анализа в виде mindmap

Для создания mindmap используйте draw.io. В центре разместите блок «Безопасность данных». От него протяните стрелочки и разместите следующий уровень — выделенные категории данных. На следующем уровне укажите, какие именно данные компании относятся к этой категории. Для каждого типа данных укажите риск и присвойте ему оценку. На последнем уровне объясните, почему вы оценили риск именно так.

Когда mindmap будет готов, загрузите его в директорию Task1 вашего репозитория.

## *С какими типами данных работает компания?*

### Публичные данные

- данные онлайн витрины недвижимости

    **Риски** - искажение данных, т.к. если на витрине отображается неверная цена, статус квартиры или описание, то это может ввести в заблуждение клиента.

### Внутренние данные

- данные по осмотрам, бронированию и взаимодействия менеджера с клиентом

    **Риски** - потеря данных, искажение данных. Результаты осмотров и бронирований фиксируются в IT-системах, поэтому потеря или изменение таких данных может нарушить процесс продажи и сопровождения клиента

- данные об объектах недвижимости

     **Риски:** - искажение данных, некачественные данные. Эти данные используются несколькими сервисами продаж. Если статусы объектов или параметры недвижимости расходятся между системами, менеджеры и клиенты будут видеть разные данные.

- данные сервисов ЖКХ

    **Риски** - искажение данных, некачественные данные. Если данные по ремонтам, начислениям или обращениям некорректны, собственник может получить неправильную информацию или выполнить ошибочное действие.

- Данные DWH, BI и отчётности

    **Риски** - некачественные данные, обесценивание данных, утечка данных. В компании нарушен контроль внутренних потоков данных, а со стороны систем обработки данных нет ограничений на доступ к данным. Поэтому в DWH могут попадать лишние, грязные или чувствительные данные.

### Конфиденциальные данные

- персональные данные клиентов

    **Риски** - утечка данных, искажение данных, некачественные данные.
    При бронировании клиент указывает контактные данные и может заполнить расширенную форму, которая используется для онлайн-сделки . Эти данные относятся к чувствительной для клиента информации, а ошибки могут привести к отображению чужого Ф. И. О. в личном кабинете.

- персональные данные собственников
  
    **Риски** - утечка данных, искажение данных. Системы ЖКХ и CRM управляют данными собственников. Опасна ситуация, когда данные одного собственника становятся доступны другому пользователю или партнёру.

- данные партнёрских API

    **Риски** - утечка данных, искажение данных, некачественные данные.
    API управляющих компаний используются без единых политик безопасности и системного контроля, а контракты API могут содержать персональные данные . Более того, внешний пользователь может увидеть или изменить данные, к которым у него не должно быть доступа.

- данные финансового учёта
  
    **Риски** - утечка данных, потеря данных, искажение данных. Финансовые данные важны для бухгалтерского учёта, сверок, отчётности и платежей. Ошибка или потеря таких данных может привести к финансовым расхождениям и претензиям.

- данные аутентификации и авторизации

    **Риски** утечка данных, искажение данных.
    Если права доступа или связка пользователя с профилем настроены неверно, пользователь может увидеть чужие данные

### Секретные данные

- данные онлайн-сделок

    **Риски** - утечка данных, искажение данных, потеря данных.
    Онлайн-сделка описана как сложный технический и юридический процесс с интеграцией с госорганами. Искажение данных сделки может привести к юридически ошибкам, а утечка — к серьёзному ущербу для клиента и компании.

- документы и данные для регистрации сделки
  
  **Риски** - потеря данных, искажение данных.
  Потеря или изменение таких данных может остановить сделку или привести к неправильной регистрации.

- данные управления «Умным домом»

    **Риски** - утечка данных, искажение данных.
    Собственники могут управлять автоматикой и устройством, которое запирает квартиру. Несанкционированный доступ или изменение таких данных уже влияет не только на информационную безопасность, но и на физическую безопасность жильцов.

- критичные интеграционные и технические данные
  
    **Риски** - утечка данных, потеря данных. Если такие данные будут раскрыты, злоумышленник сможет получить доступ к чужим данным или выполнять действия от имени системы.
