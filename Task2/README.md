# Задание 2. Разработка и заполнение проверочного листа для бизнес-систем

Теперь вам необходимо составить проверочный лист безопасности для бизнес-систем.

Для этого:

- Проанализируйте схему и описание системы. Идентифицируйте системы и изучите характер их работы с точки зрения безопасности.
- Выберите, какие разделы включить в проверочный лист, исходя из проблем и приоритетов компании. Подробно объясните свой выбор — это важная часть решения.
- Оформите проверочный лист в виде Markdown-таблицы. В таком формате и вам, и ревьюеру будет легче отслеживать изменения в решении. При составлении листа можете опираться на шаблон, который мы дали в шестом уроке первой темы. Вот он в нужном формате. Заполните все поля проверочного листа, для которых достаточно данных.
  
Когда будете сдавать решение, загрузите проверочный лист в директорию Task2 в рамках пулл-реквеста.

## Решение

### ИТ-ландшафт организации

**Системы.**

- продажи: витрина, онлайн-тур, онлайн-сделка, CRM, данные недвижимости;
- ЖКУ: приложение собственника, CRM собственников, оплаты ЖКХ, ремонт, “Умный дом”;
- финансы: финансовый учёт, БД, служба каталогов;
- Data: DWH, BI, отчётность, будущие ML/AI-сервисы.

**Данные.** Компания обрабатывает ПДн клиентов и собственников, данные сделок с недвижимостью, финансовые данные, данные ЖКУ, данные об объектах недвижимости, данные партнёрских интеграций и данные для BI/ML/AI.

**Инфраструктура.** Сервисы размещены в собственном ЦОД, приватном облаке и частично в гибридной инфраструктуре. Для внешнего доступа используется firewall, для БД настроены резервные копии.

### Выбрать разделы для включения в проверочный листы

I. Управление доступом — обязательно, потому что клиенты видят чужие данные, партнёрские API позволяют доступ к чужим объектам, а Data-системы не ограничивают доступ.

II. Безопасность данных — обязательно, потому что есть ПДн, несистемные потоки данных, BI/DWH, планы ML/AI и требования законодательства.

III. Защита инфраструктуры — обязательно, потому что есть собственный ЦОД, приватное облако, гибридная инфраструктура, внешние клиентские приложения и партнёрские интеграции.

IV. Управление инцидентами — желательно, потому что компания опасается утечек, уже есть жалобы клиентов на чужие данные, а аудит должен помочь предотвращать и расследовать инциденты.

V.1. Общие вопросы — включить как вспомогательный раздел: удалённый доступ, VPN, MDM, контроль устройств, облачные бэкапы.

V.2. Управление оборудованием и физическая безопасность — включить, есть собственный ЦОД.
